# R9700 public Unity integration result

The complete fixed experiment passed correctness and equal-work checks, but did **not** confirm a stable engine-frame cadence improvement under the frozen gates. The improved query did pass the gates for its native GPU query interval and explicit scene command interval in all three scenes. Those GPU intervals are narrower than a full Unity frame, and neither is OS presentation evidence. Runtime defaults remain unchanged.

Measured source: `2db2119b55c747d0a48f6bc563020cd7b47dfef4`; Release build GUID: `59161274a1224b9d92e21c09e768cbb5`. Unity 6000.5.2f1, D3D12, AMD Radeon AI PRO R9700, driver 32.0.31041.1004. The environment exposes eight logical processors. The build uses `BuildOptions.None`; runtime Development is false. All Player files, dependencies and exact configurations are hashed in the evidence folder.

Fifteen independent oracle processes preceded fifteen formal processes. All **240 arms, 92,160 frames, and 276,480 native timing scopes** passed. Complete asynchronous histories matched the corresponding CPU oracle byte for byte; all fixed streaming lifecycle events passed. There were zero formal failures and no repeated formal cells. Seven pre-collection statistical tests passed. A separate audit independently checked binary identities, process non-overlap, nested native timing intervals, history contents and all fifteen engine-cadence contrast ratios/95% intervals.

## Engine cadence and failed gates

The following comparison changes only the query (`old-full` to `new-full`). Ratios above one favor the candidate. Intervals use five process-level paired log ratios; each process contains four balanced blocks. CV must be <=5%, baseline drift <=15%, mean-ratio 95% CI lower bound >1, and p95 ratio >=1.01.

| Scene | Cadence ratio [95% CI] | Baseline CV | Candidate CV | Baseline drift | p95 ratio | Why inconclusive |
|---|---:|---:|---:|---:|---:|---|
| Sparse static | 3.237 [3.086, 3.396] | 5.777% | 3.667% | 29.346% | 2.649 | Baseline CV and drift |
| Hotspot dynamic | 84.310 [78.710, 90.309] | 0.378% | 6.824% | 0.437% | 65.180 | Candidate CV |
| Streaming switch | 3.348 [3.064, 3.659] | 2.701% | 7.529% | 17.942% | 2.640 | Candidate CV and drift |

These are substantial point estimates within this synthetic workload, but the predetermined stability criteria were not met. The old cell-serial query is particularly unfavorable for the concentrated hotspot distribution. These ratios must not be advertised as a general application, frame-rate or display improvement.

Changing both query and index gives cadence ratios 3.198 [3.046, 3.356], 90.146 [83.845, 96.919], and 3.040 [2.784, 3.320] respectively, also inconclusive. Holding the new query fixed and changing only the index gives 0.988 [0.961, 1.016], 1.069 [0.953, 1.200], and 0.908 [0.809, 1.019]. There is no confirmed consistent incremental-index frame benefit. With the old query, incremental-index cadence ratios are below one in all three scenes; the hotspot comparison is a stable observed slowdown (ratio 0.877 [0.876, 0.878], both CVs <0.4%, drift <0.5%), although the benefit-oriented gate labels it inconclusive rather than a winner.

## Missing data and tails

QPC mapping identified source Unity frames without using the delayed observation frame. Positive full-engine GPU coverage for the new-query arms did not meet the frozen 95% threshold in every block, so **all full-engine GPU comparisons involving the new query are unavailable**. For new-full/new-incremental respectively, steady-block coverage ranges were 78.12–88.44% / 68.75–86.88% (sparse), 50.00–56.88% / 64.38–71.88% (hotspot), and 73.44–86.88% / 51.25–58.13% (streaming). Zero rows remain in the raw files; they were not treated as fast frames. Available main/render CPU metrics and complete process intervals are reported separately.

OS presentation was unavailable. First screen is an engine first-rendered-EOF proxy since Unity startup, not physical display latency. Each steady block has only about 3.2 observations above p99, and each streaming arm has two content registrations; no rare-tail improvement is confirmed. Warmup and setup were not erased: complete-arm and whole-process intervals, every over-budget frame, memory/GC and load/register/cancel/unload/first-use events remain in the evidence.
